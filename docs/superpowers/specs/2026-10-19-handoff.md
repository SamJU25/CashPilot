## 2. What changed, by area

### Backend: passkey removal
- Deleted: `services/security/passkeys.py`, `tests/passkey_authenticator.py`, the `webauthn` and `cbor2` requirements, the `WEBAUTHN_*` settings (`.env.example`, `docker-compose.yml`).
- Routes: removed `POST /actions/{id}/execute`, `/passkey-options`, `/passkeys/register/options`, `/passkeys/register`. Added `POST /api/v1/actions/{id}/prepare`. `/reject` stays. A decided intent returns 409.
- Ledger: `ActionStatus` is now `STAGED_PENDING_HITL | PREPARED | REJECTED`. `biometric_signature` is gone from `StagedActionIntent`; ledgers saved earlier still load (the field is dropped on read; there's a test).
- Schemas: `requires_biometric_hitl` and `biometric_required` removed from `CopilotResponse` and `AgentActionProposal`.
- Policy output key `requires_biometric_execution` renamed `requires_owner_action` (policy JSON plus both decision adapters).
- Staging reply now says: "Nothing has been sent: review it in Approvals, then prepare the request and send it to the lender yourself."

### Model, prompts and training data
- `services/agent/prompts.py`: `sanitize_cfo_reply` now also strips reasoning that ends at an orphan `</think>`. With thinking on, the chat template opens `<think>` inside the prompt, so the model's plan was leaking into replies. Test added.
- `services/agent/local_transformers.py`: `enable_thinking` read from `LOCAL_ENABLE_THINKING` (default off).
- `contracts/decision_tables/agent_persona_policy.json`: new rule 6 (mention every figure the question touches, thresholds included), rule 5 now also forbids adding or combining figures, and "approval before execution" wording became "the owner sends it".
- Knowledge cards: `app_safety.md` "Tier 3: Passkey-Approved Execution" is now "Tier 3: Owner-Sent Actions"; passkey lines in `cash_liquidity.md` and `financing.md` are rewritten.
- `scripts/generate_finetune_dataset.py`: about 40 passkey strings rewritten. `dataset/` regenerated (4,610 / 511 / 250 rows, 0 passkey mentions, `verify_dataset_health.py` PASS).
- **`sme-finance-dataset.zip` (repo root) rebuilt from the new `dataset/`.** This is what the owner uploads to Kaggle. The old zip is kept as `dataset.zip` (identical to the old data; neither zip is in git).

### Eval tooling
- `scripts/eval_model.py`:
  - `--engine production`: runs the real path (4-bit base plus adapter via `LocalTransformersEngine`, reply sanitized).
  - Flags `--thinking on|off`, `--limit_per_suite N`.
  - Reports latency, empty/cut-off replies, invented figures, and a **delivered** pass rate (what the owner sees after the supervisor's off-topic refusal and invented-figure fallback).
  - Seeds use `zlib.crc32` (the earlier `hash()` was salted per process).
  - "0 NSF" is accepted as "no NSF" or "zero NSF".
  - The tier-3 gate checks that the reply leaves sending to the owner and never claims money moved.
- `scripts/build_eval_set.py`: suite 5 renamed "Owner-Sent Actions" (`requires_owner_handoff`). `dataset/eval_set.jsonl` rebuilt.

### Tests
- `tests/unit/test_security_gate.py` rewritten for prepare and dismiss. The auth, e2e and integration tests now check that execute/passkey routes don't exist and that prepare works once.
- **Fixed a destructive test:** `tests/security/test_backend_hardening.py::test_delete_model_adapter_guard_still_holds` called the real `delete_model()` and deleted `models/base/MiniCPM5-2B` (5 GB). It now stubs `shutil.rmtree`; verified with canary files. The weights were re-downloaded.
- Result: **854 passed, 1 skipped** (15 passkey-only tests removed).

### Frontend (all screens)
- Passkey UI removed. Approval cards offer **Prepare request** (pre-filled lender request to copy or download) and **Dismiss**; both call the ledger in live mode, and a failed call leaves the card pending.
- `lib/api.ts`: one client for analyze, underwrite, invoices, chat, actions (list, prepare, reject), test-connection, health. 60 s timeout, 180 s for chat.
- `app/api/session/route.ts`: issues the tenant token server-side, so the enrollment key never reaches the browser. It answers only under `next dev` or with `CASHPILOT_OPEN_SESSION=1`, and checks Origin against CSRF.
- Wired screens: Statements upload, Receivables (invoice CSV upload), Funding, Overview figures, Assistant chat, Approvals, Settings "Test connection", and a sidebar server status (polls `/health` every 30 s).
- Money shows in the data's own currency (€ for EUR statements).
- 6 UI languages kept in sync for every new string.

### Environment
- PyTorch is the CUDA build `2.14.1+cu132`, plus `bitsandbytes`, on an RTX 4050 Laptop GPU (6 GB). `requirements-local.txt` now lists the cu132 index, so a fresh install gets the GPU build.
- Local dev tenant key: `.env.local` (Next.js) and the `env` block in `.claude/launch.json` (backend). Both are gitignored; `.env*.local` was added to `.gitignore`.

## 4. Known gaps

1. **The deployed adapter was trained on the old zip**, so it still leans on passkey or "app sends it" phrasing. Only retraining on the new zip fixes this.
2. **56% eval pass rate (62% as delivered).** Remaining causes: replies leave out required figures (23), state figures the engine did not produce (11), and multi-turn follow-ups lose earlier figures. Prompts now forbid combining figures; the fine-tune data should teach restating every figure, especially across turns.
3. Backend endpoints the frontend still needs (details in `docs/superpowers/specs/2026-10-19-wiring-gap.md`):
   - forecast on `/analyze`
   - `GET /analyze/series`
   - a what-if route for `calculate_cash_scenario`
   - chat `steps`
   - `GET /events`
   - account display names
   - FX
4. `resolve_tenant_identity` still trusts a client-sent `X-Tenant-ID` when no token is sent. Read-only data routes must require a token before any hosted deploy.
5. `/underwrite` takes one file, so with several CSVs only the first is scored.
6. Backend advisory texts (`summary_advisory`, `recommended_actions`, `conditional_proposal`) are English only.
